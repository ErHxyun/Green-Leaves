# 小绿叶内容工作台使用说明

打开 http://localhost:8080/admin，使用管理员密钥登录。刷新页面后需要重新登录。

## 去哪里修改内容

| 想做的事 | 后台入口 |
|---|---|
| 编辑活动文章、中英文标题、活动照片 | 活动内容 |
| 修改某一年的标题与摘要 | 年份管理 |
| 上传图片、查找已上传照片 | 图片资料 |
| 修改首页介绍、关于我们、联系方式说明、导航、页脚 | 页面文案 |
| 换首页轮播、寄语图片、人物照片、二维码、Logo | 页面图片 |
| 找活动、咨询操作、润色一条页面文案 | AI 小助手 |
| 将 Word 或文章整理成新活动草稿 | 活动草稿助手 |

目前有 10 个年份、42 个原始活动、1086 个活动内容块、65 项页面文案（中英文共 130 条）以及 8 个页面图片位置（19 张原始图片）。
寄语图片里的文字仍是图片内容；更改时替换图片，不会自动识别或改写图片中的公益事实。

## 保存和发布

- **保存草稿**：保存修改，官网继续显示上一次发布的版本。
- **发布／更新到官网**：审核无误后，将当前内容更新到官网。
- **归档活动**：将活动从公开接口移除。
- **恢复历史版本**：恢复成草稿，仍须单独发布。
- 新建草稿从未发布过，因此不会出现在官网。
- 活动、年份、页面文案和页面图片都遵循这个规则。若其他编辑者已修改活动或页面图片，出现冲突时请重新读取，避免覆盖。

API 故障时，官网仍可能显示原有内置内容；这份离线回退不是实时发布版本，可能包含后来已归档的活动。

## 编辑一篇活动

1. 在“活动内容”搜索并打开活动，或点击“新建活动”。
2. 填写年份、中英文标题及可选日期。唯一链接名称只允许字母、数字、连字符与下划线。
3. 添加正文、小标题或图片，用上下移动调整顺序。
4. 图片可从资料库选取，也可在选图窗口直接上传。
5. 查看中文、英文预览，保存草稿。
6. 审核内容、事实和敏感信息后，独立点击“发布活动”。

未知数字、日期或事实请核对来源，不要自行猜测。发布活动需要已有公开版本的年份、英文标题及英文正文回退。

## 页面文字与图片

“页面文案”按首页、我们的努力、关于我们、联系我们、导航、页脚和通用分组。点击中文名称及正文预览卡片，也可以搜索官网上的文字。
中文和英文分别编辑；保留双大括号中的占位符（例如 year）。浏览器标题、搜索描述在“通用”分组；搜索描述原值还是旧 CRA 默认说明，需要按实际内容编辑。

“页面图片”先选择位置，再更换图片。首页轮播和寄语可增加、移除、上下移动；其他位置是单图。图片替代文字用于无障碍阅读，资料说明供编辑参考，不会增加官网可见版式。

上传支持 JPG、PNG、WebP，单张不超过 10 MB / 4000 万像素；不支持动画。可拖入一张图片或选择文件。服务器会转换为 WebP、校正方向并去除 EXIF 元数据。
上传后的图片链接可访问，但上传图片本身不会发布活动。不要把图片资料库当作私密文件存储。

## 上传 Word 或文字资料

在两个助手中均可上传 .docx 或 UTF-8 .txt，单文件最多 10 MB，正文最多 100000 字符。
上传只提取正文和表格文字，不自动交给 AI，也不会创建或发布活动。先检查导入文本，再点击发送或生成。
旧 .doc 请另存为 .docx。图片、页眉页脚和 Word 排版不导入。
在 AI 小助手中点击“整理为活动草稿”，可把导入资料带到活动草稿助手。

## AI 小助手

可以试着说：
- “帮我找到 2023 年的活动。”
- “怎样替换联系我们的二维码？”
- 选中一条页面文案后说：“保留所有数字，帮我润色英文，中文保持不变。”

助手提出修改时显示前后对照。核对提醒并勾选确认，才能“接受文案修改为草稿”。原文已经变化时，会拒绝覆盖；请重新生成。
接受不会发布。到“页面文案”中检查后再更新到官网。助手不会自动发布、归档、换图片或批量改写既有活动。
历史对话存储在本地数据库，仅管理员可访问。发送给助手时，相应资料会交给配置的模型服务处理。

## 活动草稿助手

导入或粘贴文章 → 生成待审核建议 → 核对原始资料、中英文结果及提醒 → 接受为草稿 → 打开活动编辑 → 独立发布。
AI 不确定的数字、日期和隐私信息必须人工审核。没有确认年份的建议不能直接接受；应先补全来源或手工编辑。

## 维护者说明

- 后端配置文件：backend/.env；管理员登录使用 ADMIN_API_KEY，AI 使用所选 provider 的独立密钥。
- 当前 provider：OpenRouter，可配置 deepseek/deepseek-v3.2。不要将任何密钥写入前端变量或提交 Git。
- 上传图片默认保存 backend/uploads；可用 UPLOAD_DIR 修改位置。Compose 使用 media_uploads 卷。
- 备份必须包含 PostgreSQL 和图片目录/卷；数据库备份不包含图片。不要执行会删除数据卷的 docker compose down -v。
- 发布快照在 published_content，版本记录在 content_versions；两者与编辑操作在事务中更新。
- 运行迁移后执行 seed，可补齐新增页面内容，不覆盖已有人工编辑。
- 新接口：GET/PUT /api/admin/pages（更新时附带 /:id）；POST /api/admin/documents/extract；GET /api/admin/assistant/threads；GET /api/admin/assistant/threads/:id；POST /api/admin/assistant/messages；POST /api/admin/assistant/proposals/:id/accept 或 reject。
- 真实助手测试：从项目根目录执行 node --env-file=backend/.env backend/scripts/assistant-live-smoke.js。使用模拟文本与隔离数据库，会产生少量模型费用。
- 独立成员账号、外网部署、定时自动备份尚未配置。本版后台仍使用管理员密钥。
